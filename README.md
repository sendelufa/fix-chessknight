# Chess Knight — API расчёта минимального числа ходов коня

Веб-приложение на Java, которое вычисляет минимальное число ходов шахматного
коня между двумя клетками прямоугольной доски. Проект объединяет алгоритм
поиска в ширину (BFS) и два HTTP-интерфейса: REST на Spring MVC и Java Servlet.

## Возможности

- **Поиск кратчайшего пути:** алгоритм BFS последовательно исследует
  допустимые ходы коня по уровням.
- **Два HTTP-интерфейса:** REST и Servlet используют общую реализацию сервиса
  расчёта.
- **Настраиваемый размер доски:** поддерживаются прямоугольные доски
  с размерами от 2 до 1 000 по каждому измерению по умолчанию.
- **Шахматные координаты:** названия клеток, например `A1`, `B3` и `AA10`,
  принимаются без учёта регистра.
- **Автоматические тесты:** результаты алгоритма, валидация и поведение
  контроллеров проверяются с помощью JUnit, Spring Test и Mockito.
- **Сборка Maven:** приложение упаковывается в WAR; GitHub Actions запускает
  сборку при отправке изменений в репозиторий.

## Быстрый старт

### Требования

- JDK 8 — соответствует настройкам компиляции и CI проекта.
- Maven, доступный через команду `mvn`; Maven Wrapper в репозитории отсутствует.
- Git для клонирования репозитория.

### Клонирование и запуск

```bash
git clone https://github.com/sendelufa/fix-chessknight.git
cd fix-chessknight
mvn spring-boot:run
```

Базовый адрес приложения: `http://localhost:8080/hourse`.
Написание `hourse` соответствует текущему пути приложения и имени WAR-файла.

### Пример запроса

```bash
curl --get 'http://localhost:8080/hourse/rest/count' \
  --data-urlencode 'width=10' \
  --data-urlencode 'height=14' \
  --data-urlencode 'start=B1' \
  --data-urlencode 'end=A3'
```

Ожидаемое тело ответа:

```text
1
```

Конь может перейти из `B1` в `A3` за один ход. Этот сценарий также проверяется
в тестах алгоритма и контроллеров.

## Документация API

### Эндпоинты

| Метод | Путь | Тело успешного ответа |
| --- | --- | --- |
| `GET` | `/hourse/rest/count` | Целое число, сериализованное Spring MVC |
| `GET` | `/hourse/servlet/count` | Целое число в формате `text/plain` |

Оба эндпоинта принимают одинаковые параметры запроса и возвращают HTTP `200`
при успешном расчёте.

### Параметры запроса

Все четыре параметра обязательны.

| Параметр | Тип | Описание | Пример |
| --- | --- | --- | --- |
| `width` | Целое число | Ширина: от 2 до заданного максимума | `10` |
| `height` | Целое число | Высота: от 2 до заданного максимума | `14` |
| `start` | Строка | Начальная клетка: буквы столбца и номер строки | `B1` |
| `end` | Строка | Конечная клетка в том же формате | `A3` |

Столбцы обозначаются буквами (`A`–`Z`, `AA`, `AB`, …), строки — числами от 1.
Координаты должны находиться в пределах заданной доски. Особенности обработки
границ и валидации описаны в разделе
[«Известные ограничения»](#известные-ограничения).

### Значения результата

| Значение | Описание |
| --- | --- |
| `0` | Начальная и конечная клетки совпадают |
| Положительное целое число | Минимальное число ходов, найденное алгоритмом |
| `-1` | Алгоритм не нашёл путь до конечной клетки |

Тело ответа содержит одно число, а не JSON-объект с именованным полем.

Аналогичный запрос к Servlet:

```bash
curl 'http://localhost:8080/hourse/servlet/count?width=10&height=14&start=B1&end=A3'
```

### Обработка ошибок

REST-эндпоинт возвращает HTTP `400`, если обязательные параметры отсутствуют
или Spring MVC не может преобразовать их значения в целые числа. Servlet
явно возвращает HTTP `400` с текстом `error. not valid input params`
при некорректных числовых значениях или ошибке проверки размеров доски.

Обработка ошибок пока различается между интерфейсами: пользовательские
исключения валидации не всегда преобразуются в ответы HTTP `400`.

## Как работает алгоритм

Доска представлена невзвешенным графом: клетки — вершины, допустимые ходы
коня — рёбра. Из каждой клетки возможны до восьми ходов.

1. Начальная клетка отмечается как посещённая.
2. Формируется следующий уровень возможных ходов коня.
3. Исключаются клетки за границами поиска и уже посещённые клетки.
4. При достижении конечной клетки возвращается номер уровня.
5. Если клеток для дальнейшего поиска не осталось, возвращается `-1`.

BFS находит кратчайший путь в исследуемом графе, поскольку каждый новый уровень
соответствует одному дополнительному ходу. Приложение возвращает только число
ходов, без восстановления самого маршрута.

Количество исследуемых клеток может быть пропорционально `width × height`.
Посещённые клетки хранятся в памяти. Реализация также выделяет целочисленный
массив размером с доску. Двунаправленный поиск и эвристическое сокращение
области поиска не реализованы.

## Структура проекта

```text
src/
├── main/
│   ├── java/ru/sendel/
│   │   ├── App.java                 # Точка входа и регистрация Servlet
│   │   ├── controller/              # HTTP-интерфейсы REST и Servlet
│   │   ├── service/                 # Общий сервис расчёта
│   │   │   └── chess/               # BFS, доска, клетки и параметры запроса
│   │   ├── response/                # Абстракции ответов
│   │   ├── exception/               # Исключения валидации
│   │   └── config/servlet/          # Фильтр и слушатель Servlet
│   └── resources/
│       └── application.properties  # Настройки сервера и доски
└── test/java/ru/sendel/test/         # Тесты алгоритма и HTTP-интерфейсов
```

Оба контроллера создают `KnightMovesParams` и обращаются к `IKnightService`.
`KnightChessService` делегирует поиск классу `ChessKnight` и оборачивает
результат в `NumberMovesResponse`.

## Известные ограничения

- BFS использует строгие проверки верхних границ (`column < width`
  и `row < height`), поэтому последний столбец и последняя строка исключаются
  из генерируемых ходов. Это может приводить к неверным результатам
  для маршрутов, проходящих через эти границы.
- Разбор координат не требует совпадения со всей строкой и не отклоняет
  строку доски `0`. Валидацию и HTTP-ответы об ошибках необходимо унифицировать.
- Servlet хранит данные запроса в полях экземпляра. Для корректной обработки
  параллельных запросов эти значения следует перенести в локальные переменные.
- Проект использует Java 8 и Spring Boot 2.1.6. Следующие направления развития —
  обновление зависимостей и расширение тестов граничных случаев.
